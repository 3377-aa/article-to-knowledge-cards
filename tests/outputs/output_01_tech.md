# 知识卡片 · HTTP 缓存入门（来源：test_tech_tutorial.md）

共 5 张卡片。

## 卡片 1：强缓存靠 max-age

- **核心知识**：`Cache-Control: max-age=31536000` 表示资源在 31536000 秒内可直接从本地缓存读取，完全不请求服务器。
- **简明解释**：强缓存是性能最好的缓存方式，因为浏览器连网络请求都不发。有效期内的资源直接读本地副本。
- **例子/自测**：`app.js` 的响应头写了 `max-age=86400`，同一用户当天第二次打开页面时，浏览器会向服务器发请求吗？（答：不会）

## 卡片 2：no-cache 不是"不缓存"

- **核心知识**：`no-cache` 的含义是"缓存但每次使用前必须向服务器验证是否过期"，而不是禁止缓存。
- **简明解释**：这个指令名有误导性。它仍然把资源存到本地，只是每次使用前都要问服务器"还能用吗"。
- **例子/自测**：某开发想让 HTML 完全不进缓存，于是给 HTML 加了 `Cache-Control: no-cache`。这个做法符合 no-cache 的真实语义吗？（答：不符合，no-cache 仍然会缓存并在使用前验证）

## 卡片 3：协商缓存靠成对头部验证

- **核心知识**：协商缓存由两组配对头部工作：响应中的 `Last-Modified`／`ETag` 对应请求中的 `If-Modified-Since`／`If-None-Match`；资源未变时服务器返回 304 且不带响应体。
- **简明解释**：强缓存过期后，浏览器带着上一次的标识去问服务器"变了吗"。没变就回 304，浏览器继续用本地副本，省掉了响应体的传输。
- **例子/自测**：服务器返回 304 时，浏览器会重新下载资源内容吗？（答：不会，304 不带响应体，继续用本地缓存）

## 卡片 4：ETag 比 Last-Modified 更可靠

- **核心知识**：ETag 比 Last-Modified 更可靠，因为修改时间只能精确到秒，且文件内容未变但被重新保存时修改时间也会改变。
- **简明解释**：Last-Modified 只看时间戳，会被"重新保存"这类无意义改动误导；ETag 校验的是资源本身的指纹，能识别内容是否真的变了。
- **自测**：一个文件内容完全没动，只是被编辑器重新保存了一次。用 Last-Modified 和 ETag 分别校验，结果会有什么不同？

## 卡片 5：静态资源长缓存 + HTML no-cache

- **核心知识**：对带 hash 文件名的静态资源使用一年强缓存，对 HTML 使用 `no-cache`。
- **简明解释**：文件名里带 hash 的资源，内容一变文件名就变，等于缓存自动失效，所以可以放心长缓存；HTML 是入口文件，必须让用户每次拿到最新版本。
- **例子/自测**：生产环境把 `app.3f2b1c.js` 的缓存设为一年，这个配置为什么是安全的？（答：内容更新后文件名 hash 会变，成为新的 URL）
