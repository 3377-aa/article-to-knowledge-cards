# HTTP 缓存入门

缓存是 Web 性能优化的核心技术之一。本文介绍 HTTP 缓存的基本机制，重点是浏览器缓存。

## 强缓存

强缓存通过响应头控制。服务器返回 `Cache-Control: max-age=31536000` 表示资源在 31536000 秒（一年）内可以直接从本地缓存读取，完全不需要请求服务器。这是性能最好的缓存方式，因为它连网络请求都不发。

另一个常用指令是 `no-cache`。注意它的名字有误导性：`no-cache` 不是"不缓存"，而是"缓存但每次使用前必须向服务器验证是否过期"。

## 协商缓存

强缓存过期后，浏览器会使用协商缓存向服务器确认资源是否真的变了。协商缓存依赖两组配对的头部：服务器首次响应时给出 `Last-Modified`（资源最后修改时间）和 `ETag`（资源的唯一指纹），浏览器下次请求时带回 `If-Modified-Since` 和 `If-None-Match`。如果资源没变，服务器返回 304 状态码，不带响应体，浏览器继续用本地缓存。

ETag 比 Last-Modified 更可靠，因为修改时间只能精确到秒，而且文件内容没变但被重新保存时时间也会变。

## 缓存决策

实践中常见的策略是：对带 hash 文件名的静态资源（如 `app.3f2b1c.js`）使用一年强缓存，因为文件名变了缓存自然失效；对 HTML 文件使用 `no-cache`，保证用户每次拿到最新入口。

## 小结

总结一下：强缓存靠 `Cache-Control` 的 `max-age`，不发请求；协商缓存靠 `Last-Modified`/`ETag` 配对验证，命中时返回 304。静态资源用长缓存加文件名 hash，HTML 用 no-cache。
